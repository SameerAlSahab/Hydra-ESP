Hydra-ESP

A wireless security research firmware for the ESP32. Runs its own management access point and web interface, and packs Wi-Fi and Bluetooth attack modules used for testing networks and devices you own or are authorized to test.

★ Star on GitHub Latest release License Companion paper

Hardware

RequiredESP32 DevKit V1, or any board on the same Xtensa LX6 chip (e.g. ESP32-WROOM-32, ESP32-WROVER)
Not supportedESP32-S2, S3, C3 and other variants — different radio hardware
OptionalSSD1306 OLED (128×64, I2C) — auto-detected on boot, shows attack status and captured passwords

Wi-Fi modules

Deauthentication

Sends forged deauth/disassociation frames to drop up to 16 targets at once. Frames-only or frames+disassoc mode. Doesn't work against clients with 802.11w (MFP) enabled — see BSSID Clone below.

WPA Handshake Capture

Forces a re-auth with a short deauth burst, then records the resulting 4-way handshake to .pcap / .hccapx for offline auditing with Hashcat or Aircrack-ng. Needs a connected client present.

Clientless PMKID Capture no client needed

Grabs the PMKID from the first EAPOL frame during association — works with just the AP in range, no connected client required. Auditable offline with Hashcat mode 22000.

Evil Twin verifies password

Clones the target SSID as an open AP and deauths the real one, pausing once a client joins the clone. A captive portal collects the password — then the firmware actually connects to the real AP with it to confirm it's correct before reporting anything, retrying on a wrong guess instead of just logging whatever was typed.

BSSID Clone (Twin-Deauth) bypasses MFP

Clones SSID, BSSID, and channel so the real AP and the clone look identical. Clients drop the connection from the resulting address conflict rather than a forged frame — which is why it still works against 802.11w/WPA3-hardened clients.

SSID Cloner

Stands up several APs sharing the target's SSID (differentiated by trailing whitespace). Adds to the same visual confusion as beacon spam.

Beacon Spam

Floods the area with 1–100 fake beacon frames carrying randomized SSIDs, cluttering every nearby scan list.

Ghost Mode (probe harvesting)

Listens for the SSIDs nearby devices probe for from their saved-network list, then advertises those exact names so devices try to auto-reconnect to the ESP32 instead.

Bluetooth / BLE modules

BLE Spam

Broadcasts BLE advertisements mimicking Apple, Samsung, and Google proximity-pairing payloads — AirPods, Galaxy Buds, Apple TV/HomePod setup, Vision Pro, and more. Triggers the matching OS-level popup on nearby devices. Target type is selectable; MAC rotation supported.

BT Payload

Advertises the ESP32 as a Bluetooth HID keyboard (Hydra-#####). Once a host manually pairs, it runs a pre-set keystroke payload — bundled options range from a harmless sound prank to a script that reads a Windows host's saved Wi-Fi passwords via netsh and posts them back to the device.

Deauth attack detector

The one defensive module: puts the radio into promiscuous monitor mode and watches for more than 10 deauth frames from one BSSID within a second, or any deauth frame from the reserved broadcast source 00:00:00:00:00:00 — both are recognized signatures of an active deauth attack. Results show up in a live log in the web UI. It can't run at the same time as an attack module, since both need exclusive use of the one radio.

Installation

1

Grab the firmware. Download the latest release, or build from source with ESP-IDF.

2

Flash it.

command line
esptool.py -p (PORT) -b 460800 --before default_reset --after hard_reset 
--chip esp32 write_flash --flash_mode dio --flash_size detect 
--flash_freq 80m 0x1000 build/bootloader/bootloader.bin 
0x8000 build/partition_table/partition-table.bin 
0x10000 build/projecthydra-32.bin 0x190000 build/storage.bin

or windows GUI tool
FILE ADDRESS
bootloader.bin 0x1000
partition-table.bin 0x8000
projecthydra-32.bin 0x10000
storage.bin 0x190000
3

Connect. Join the hydra Wi-Fi network and open 192.168.4.1 in a browser.

4

Change the defaults. Set a new AP SSID and password from Settings before doing anything else.

Legal & ethics

Educational and authorized-testing use only Only run this against networks and devices you own, or have explicit written authorization to test. Unauthorized use is illegal under the Computer Fraud and Abuse Act (US), the Computer Misuse Act (UK), the ICT Act (Bangladesh/India), and equivalent laws in most other jurisdictions. The author accepts no liability for misuse — see the companion paper (linked below) for how each attack works and how to defend against it.
